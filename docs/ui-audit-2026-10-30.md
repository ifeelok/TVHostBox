# UI/UX 诊断与优化清单（2026-10-30，基于 v1.2.3 真机截图 + 代码走查）

> 依据：1920×1080 真机截图（CM311-1sa，Android 9）三个页签 + 全部界面代码逐行走查。
> 原则：保留品牌色（深海蓝 #4FC3F7 强调色）与全部功能，只动视觉层级与交互细节。

## 一、问题诊断（按严重度排序）

### P1 页签行：三个按钮平分整行，焦点块失控
- **现象**：`nav_bar` 三个页签各占 1/3 屏宽、高 50dp。焦点白块横跨约 600px（1/3 屏），
  视觉重量压过内容区；「扫码配置」「CF 优选」未聚焦时只是一行灰字漂在大片空白里，
  没有任何"这是个按钮"的形态；页签行连同 padding 占掉约 64dp 垂直空间。
- **违反**：焦点应"贴住内容"（Fitts 视觉反馈）、控件应有可供性（affordance）、
  10-foot 布局的垂直空间应尽量让给内容。

### P2 列表行密度：一行 ~64dp，一屏只能看 5 行
- **现象**：行 minHeight 56dp + 内容上下 padding 8dp + 两行文字，实际行高 ~64dp。
  720dp 高的屏幕只见约 5 行；hosts 有几十条时翻页成本高（虽有长按加速）。
- **违反**：列表类界面的"信息吞吐量"原则——TV 上行高要大，但 64dp 已超出可读下限。

### P3 行副行文案松散
- **现象**：`127.0.0.1   ·   第 1 行` 用三个全角空格夹 `·` 分段，横向浪费明显，
  长域名 + 长 IP + 注释时更容易触发省略号截断。

### P4 底部提示条偏小
- **现象**：键帽 11sp、说明 13sp。3 米外勉强可辨，未达到"扫一眼"的标准。
  提示条是这套交互的核心教学工具，字号不够等于白做。

### P5 CF 进度条空态不可见
- **现象**：进度轨道用 `alpha(border, 0.9)` 画在卡片上，对比度过低——
  没开始测速时用户根本找不到"条"在哪，只有右侧孤零零一个 "—"。

### P6 列表选中行高亮顶到卡片圆角
- **现象**：ListView 与卡片边框之间没有 padding，第一行选中时高亮块直接压在
  卡片圆角和描边上，显得毛糙。

## 二、优化清单（本次已实施）

| # | 优化 | 改动位置 | 结果 |
|---|---|---|---|
| 1 | 页签改 wrap 内容宽 + 40dp 高 + 20dp 水平内距 + 10dp 间距，左对齐 | activity_main.xml | 焦点块贴住文字；省出 ~24dp 垂直空间 |
| 2 | 非激活页签给 暗块+细描边 的按钮形态 | Skin.tabIdle | 三个页签都可点、可扫 |
| 3 | styleNav 清除 Button 自带 88dp 最小宽高 | MainActivity.styleNav | 防止紧凑页签被撑回原形 |
| 4 | 行高 56→50dp、内容 padding 8→6dp、序号徽章 26→24dp、竖条 34→30dp | newRowHolder | 一屏可见 6~7 行 |
| 5 | 副行文案 `IP · N 行 · 注释` 紧凑分隔 | HostsSideList.bindRow | 减少截断、更整齐 |
| 6 | 键帽 11→12sp（padding 9/3dp）、说明 13→14sp | newKeyCap/newHintLabel | 3 米外可读性提升 |
| 7 | 进度轨道改 `alpha(text, 0.16)`、条高 6→7dp | buildCfPanel | 空态也能看到轨道 |
| 8 | 列表容器上下加 5dp 内距 | SideList 构造 | 高亮不再压圆角描边 |

## 三、评估过但暂不改动（记录取舍）

- **底部按钮等宽铺满**：保留。TV 遥控器的命中目标宜大不宜小，等宽是安全解。
- **副行文字对比度**：`hint #93A6C2` 在 `card #16223A` 上对比度 ≈ 6.4:1，达标（≥4.5:1），不动。
- **对话框**：已主题化，但本轮无法真机验证弹窗，留待装机复验后再调。
- **六套主题色板**：品牌色保留，未动任何一个主题定义。
